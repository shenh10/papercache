GLM-5.4: Toward Generalized Coding with Our First Loop Transformer

发表时间: 2026-11 · Blog post by Z.ai / Zhipu AI (z.ai)

原文: https://z.ai/blog/glm-5.4

速读

一句话结论 GLM-5.4 通过继续训练 750B 参数预训练基座，构建了首个旗舰级 Loop Transformer（让权重共享的层在单次前向中多轮迭代的循环架构），在不增参下达到 2T-3T 参数模型相当的智能水平，实现非高峰最高 200 tokens/s 吞吐，并开启了以代码解决跨领域任务的 Generalized Coding（广义编程）。

要解决什么问题 大规模软件工程、网络安全、3D 建模和物理控制均需跟踪多步因果链并维持全局逻辑一致；不同于靠参数记忆的任务，这类超长链推理真正需要更多有效计算深度，而非单纯堆叠参数。2018 年 Universal Transformer（权重共享深度循环架构）虽能提高参数效率，但从头预训练在同等算力下仍落后于非共享模型。若直接把已有基座改为多轮循环，在 750B 参数与 1M 上下文下还有三道卡点：直接覆写隐藏状态会令跨轮次激活范数膨胀，使下游层收到偏离预期尺度与分布的表示；每轮保存完整 KV Cache（键值缓存）会使显存随循环次数翻倍，推高部署成本；每轮重算稀疏注意力索引增加检索开销，循环还会放大内核间显存读写碎片化，拖慢吞吐。

怎么做的 核心思路是不再从零预训练，而是基于已预训练的 750B 参数 GLM-5 基座，抽取 28 层执行 2 轮权重共享循环，经继续训练改造成循环架构，从而绕开从头训练算力效率偏低的短板，以较小额外算力在不增参下加深计算深度。围绕大规模落地卡点，设计包含四个关键部件。第一是 Gated Progressive Updates（门控渐进更新），为每轮加入独立逐 token 门控，按比例将候选更新写回残差流，抑制激活范数膨胀并稳住下游分布；训练后门控自发分工：第一轮构建全局上下文并小值保守写入，第二轮复用该状态打开门控做完整精炼，且能按 token 难度动态调步长，在较难 token 上于第一轮更积极写入，让复杂预测从迭代精炼中获益更多。第二是 Hybrid KV Cache（混合键值缓存，结合全局共享与独立滑动窗口），第二轮复用第一轮选出的稀疏 KV，同时在局部滑动窗口内保留新生成的 KV；两路 KV 可在同一位置重叠，兼顾第一轮全局表示与第二轮局部更新，将额外循环的显存代价压成一个滑动窗口，控制住 1M 上下文相对 GLM-5.3 的成本增幅。第三是 Sparse Attention Index Reuse（稀疏注意力索引复用），第二轮直接复用第一轮索引器结果，以零索引开销取得与每轮重算几乎一致的效果。第四是推理基础设施协同，通过系统级核心内核融合削减中间显存读写，消除循环放大的碎片化开销。

效果如何 作者按 Scaling Correctness（缩放正确性，指改动放大后仍有效）在 1B、4B、30B 和 750B 基座上渐进验证；原文未披露训练数据量、硬件及各基准绝对分数。对比基线涵盖三类：同构 30B 实验对比同参标准非循环基座（单次前向路线），1M 上下文部署成本对比前代 GLM-5.3，旗舰智能对标 2T-3T 参数模型（堆参路线）。受控实验经 200K 长上下文 SFT（监督微调）并开启思考模式评测，循环版仅多耗约 10% 训练算力即显著胜出：推理链越长收益越大，数学、科学推理与长上下文增幅最明显；GPQA-Diamond 与 MMLU-Pro 等多数基准平均输出长度降 10–14%，源于思维链缩短，说明部分显式推理转入隐式循环深度。旗舰 GLM-5.4 达到该层级智能，非高峰吞吐最高 200 tokens/s，高峰 70–80 tokens/s；依托编码与视觉提升，已能写代码生成音乐视频、用 FreeCAD 做 6 轴机械臂 CAD 建模、开发完整游戏，并用纯数学几何与自定义 GLSL 着色器生成交互式 3D 场景。局限上，除额外算力、滑动窗口显存及受控部署成本增幅外，作者坦言模型易陷入过长的“马拉松式思考”循环，虽稳定换来超越参数量的准确率；且循环次数固定，自适应计算及循环深度与规模继续同步放大的收益规律仍待探索。

主要贡献

过去三个月，研究团队在并行维度上同时积极扩展了循环深度（loop depth）与模型规模（model size），并由此推出旗舰模型 GLM-5.4。本文档围绕架构创新与能力范式拓展，提出了以下核心目标、问题定位与创新点：

  • 验证并落地旗舰级 Loop Transformer 架构：面对需要超长链条推理的复杂任务，单纯堆叠参数与记忆数据无法根本解决问题。研究团队构建了首个基于 Loop Transformer 架构的旗舰模型 GLM-5.4，通过跨多次迭代执行一组权重共享的层块（shared block of layers），在不增加参数量的前提下实现更深层次的推理，使 750B 规模的模型达到了可与 2T–3T 参数规模模型相媲美的智能水平。
  • 提出面向 750B 规模的继续训练与轻量化部署架构改进：针对从头预训练循环模型在同计算预算下落后于非共享模型、以及多轮循环在超大规模下带来激活分布偏移与 KV Cache 显存膨胀的问题，团队采用基于预训练基座模型的继续训练（continued training）路线，并结合门控渐进式更新（Gated Progressive Updates）、混合 KV 缓存（Hybrid KV Cache）以及稀疏注意力索引复用（Sparse Attention Index Reuse）三项核心架构改进，同时配合推理系统级核函数融合，实现了性能收益与 1M 长上下文部署成本的平衡。
  • 开启广义编程（Generalized Coding）新范式：GLM-5.4 标志着广义编程的起点。在该范式下，代码不再局限于传统软件开发，而是成为解决更广泛任务并解锁新能力的基础，依托代码与视觉能力的双重进步，进一步拓展至视频制作、工程级 CAD 建模、完整游戏开发与 3D 图形渲染等领域。
  • 明确现存局限性：GLM-5.4 目前仍存在一定不足，最显著的表现是模型容易陷入过长的“马拉松式思考”（"marathon thinking"）循环；不过，这种延长的反思与自我修正过程确实能够持续带来超越其参数量级的准确率提升。

背景与设计动机

记忆密集型任务与超长链条推理任务的根本差异。 正如团队在 GLM-5.3 技术博客中所指出的，记忆密集型任务（memory-intensive tasks）主要受益于更多的模型参数，而推理密集型任务（reasoning-intensive tasks）则主要受益于更多的有效计算量（effective compute）。诸如大规模软件工程、网络安全、3D 建模以及物理控制等场景，均属于典型的超长链条推理任务（ultra-long-chain reasoning tasks）。在这类任务中，模型必须严格遵循多步因果链条（multi-step causal chains），并在整个推理过程中维持全局逻辑一致性（global logical consistency）。仅仅依靠堆叠参数量和记忆训练数据，无法从根本上解决这类高深度推理难题，这直接驱动了团队对以循环深度增加有效计算的 Loop Transformer 架构进行探索。

方法细节

从预训练基座到 Loop Transformer

标准 Transformer 与 Loop Transformer 的前向计算机制差异。 在标准 Transformer 架构中，每一个网络层在单次前向传播（forward pass）过程中仅执行一次；而在 Loop Transformer 架构中，一组权重共享（weight-shared）的层会连续执行多次迭代（multiple iterations），在后续轮次中对前一轮迭代产出的隐藏状态（hidden states）进行持续精炼（refining）。通过这种迭代精炼机制，模型无需增加任何参数量即可获得更深的有效网络深度。

基于预训练基座继续训练的路线选择及其依据。 通过权重共享来扩展网络深度的核心思想并非全新提出：2018 年的 Universal Transformer（2018）即已提出权重共享深度（weight-shared depth）的概念，而近期关于循环深度（recurrent depth）与循环语言模型（looped language models）的研究工作也在小规模模型上证实了该方向的性能收益。然而，尽管权重共享能够显著提升参数效率（parameter efficiency），在相同的预训练计算预算（pre-training compute budget）下，从头开始训练（trained from scratch）的循环模型在性能上仍然落后于非权重共享模型。针对这一瓶颈，团队放弃了从头预训练循环模型的方案，而是选择通过继续训练（continued training）的方式，将一个已经完成预训练的基座模型（pre-trained base model）适配改造为 Loop Transformer。这一适配策略使模型得以在相对较小的计算开销（compute overhead）下显著抬升自身的智能上限（intelligence ceiling）。

750B 规模下的架构改进

GLM-5.4 的循环层配置与大规模部署权衡目标。 GLM-5.4 以 GLM-5 基座模型为起点，将其中的 28 层配置为循环层块并执行 2 次迭代（two iterations）。为了在 750B 参数规模下兼顾性能增益与实际部署成本，团队在经过大量实验验证后，引入了以下三项关键架构修改。

门控渐进式更新（Gated Progressive Updates）

多轮循环直接覆写隐藏状态引发的激活尺度失控问题。 在将一个既有预训练模型的中间层改造为多轮循环（multi-pass loop）结构时，如果直接采用覆写（directly overwriting）隐藏状态的方式，激活范数（activation norms）会在跨迭代传递过程中发生急剧膨胀（blow up）。这一现象会导致后续下游层（downstream layers）接收到超出其原有预期数值尺度（scale）与统计分布（distribution）的特征表示，进而破坏预训练基座原有的表示稳定性。

逐迭代、逐 Token 独立门控设计与训练涌现的分工机制。 为解决上述激活膨胀与分布偏移问题，GLM-5.4 为每一轮循环迭代引入了独立的逐 Token 门控（independent per-token gates），用于控制候选更新（candidate updates）按比例（proportionally）写回残差流（residual stream）。经过训练后，这些门控自发形成了明确的分工机制（clear division of labor）：

  • 第一轮迭代（first pass）：主要承担构建全局上下文（global context）的职责，以较小的门控值进行保守写入（writes conservatively），从而确保激活尺度保持稳定。
  • 第二轮迭代（second pass）：复用第一轮建立的隐藏状态以进一步精炼输出，此时门控充分打开，将完整的更新（full updates）写入残差流。
  • 基于 Token 难度的动态步长调节：上述门控还会依据单个 Token 的预测难度（token difficulty）动态调节更新步长（step size）；面对难度更高的 Token 时，第一轮迭代会以更积极的方式执行写入操作，使得复杂预测任务能够更充分地从后续迭代精炼（iterative refinement）中获益。

混合 KV 缓存（Hybrid KV Cache：全局共享 + 独立滑动窗口）

结合跨循环全局共享与局部独立滑动窗口的 KV 缓存机制。 若采用朴素（naive）的实现方式为每一轮循环迭代分别维护一份完整的 KV Cache，推理阶段的显存占用将随循环次数成倍上升。为克服这一显存瓶颈，团队在跨循环 KV 共享（cross-loop KV sharing）机制的基础上，为新增的循环轮次补充了一个局部滑动窗口（local sliding window）：具体而言，第二轮循环直接复用第一轮迭代中选出的稀疏 KV（sparse KV），同时仅在局部滑动窗口范围内保留第二轮自身新生成的 KV。值得注意的是，这两股 KV 流（two KV streams）允许在相同序列位置上重叠（overlap），从而使模型在计算注意力时能够同时关注来自第一轮迭代的全局上下文表示（context representations）以及来自第二轮迭代的更新后局部表示（updated local representations）。

超长上下文部署场景下的显存与成本控制收益。 得益于上述混合 KV 缓存设计，额外增加一轮循环迭代所带来的显存代价仅相当于一个滑动窗口大小的 KV Cache，而不再需要维护一整份完整的上下文缓存（full context cache）。在高达 1M 上下文长度（1M context lengths）的部署场景下，该机制成功将 GLM-5.4 相对于 GLM-5.3 的部署成本增幅控制在较低且可管理的范围内。

稀疏注意力索引复用（Sparse Attention Index Reuse）

跨迭代直接复用稀疏注意力索引以实现零索引开销。 GLM-5.4 所依赖的基座模型原生采用稀疏注意力（sparse attention）机制。在多轮循环推理过程中，第二轮循环直接复用由第一轮循环的索引器（indexer）所生成的注意力索引（attention indices），从而避免了重复计算索引带来的额外开销，实现零新增索引开销（adding zero indexing overhead）。团队开展的对比实验证实，直接复用首轮索引所取得的模型性能与在每一轮循环中重新计算索引几乎完全一致。

推理效率与系统协同设计

面向多轮循环架构的吞吐目标与系统级核函数融合优化。 在实际线上服务中，GLM-5.4 在非高峰时段（off-peak hours）的推理吞吐最高可达 200 tokens/s，并在高峰负载（peak load）下持续维持 70–80 tokens/s 的生成速度。要在多轮迭代执行的 Loop 架构下达成这一吞吐水平，需要模型算法设计与底层推理基础设施（inference infrastructure）之间的紧密协同设计（close co-design）。除了混合 KV 缓存与稀疏注意力索引复用在显存占用与检索开销上带来的算法级节省外，团队还在系统实现层面融合了核心计算核函数（fused core kernels），借此大幅削减中间内存的读写操作（intermediate memory reads and writes），有效消除了被循环执行所放大的碎片化系统开销（fragmented overhead）。

实验环境与评估设置

根据原文披露的信息，实验验证与模型评估的核心配置如下：

  • 验证模型规模梯度：在正式将旗舰模型切换至循环架构之前，团队在 1B、4B、30B 与 750B 四个基座模型参数量级上逐步验证了架构的扩展正确性（Scaling Correctness）。

  • 核心架构与消融模型参数：

    • 旗舰模型（GLM-5.4）：基于 750B 规模的 GLM-5 稀疏注意力基座模型，选取其中 28 层执行 2 次循环迭代，引入逐 Token 独立门控渐进式更新、混合 KV 缓存（全局共享稀疏 KV + 独立滑动窗口）与稀疏注意力索引复用，并面向最高 1M 上下文长度场景进行部署成本控制。
    • 受控等参数消融模型：采用 30B 参数规模模型进行受控等参数对比（controlled iso-parameter comparison），该 30B 模型与 750B 基座保持完全一致的架构设计；对比双方拥有完全相同的参数量，循环版本的总训练计算量（total training compute）仅比基线多约 10%。

  • 训练阶段与评测设置：30B 消融实验结果是在模型完成 200K 长上下文监督微调（200K long-context SFT） 之后测得的，且评测全程开启思考模式（thinking mode enabled）。

  • 评测基准与任务类别：原文明确提及的评测基准包括 GPQA-Diamond 与 MMLU-Pro，评测任务重点覆盖数学（math）、科学推理（scientific reasoning）及长上下文任务（long-context tasks）。
  • 硬件与软件环境：原文未公开具体的 GPU/CPU/网卡硬件型号、集群互联拓扑或底层操作系统及训练框架版本；在推理软件优化方面提及采用定制推理基础设施与核心核函数融合（fused core kernels），在广义编程演示中涉及 FreeCAD 与自定义 GLSL 着色器（custom GLSL shaders）。

实验结果与扩展正确性验证

跨规模扩展正确性（Scaling Correctness）与旗舰表现

  • 跨尺度架构有效性验证：团队将循环架构视为对扩展正确性（即任何架构改进在大规模下依然有效）的严格检验，先后在 1B、4B、30B 和 750B 基座模型上完成了渐进式验证，确认了循环深度增益可稳定扩展至超大参数规模。
  • 旗舰模型综合智能水平：基于 750B 规模基座构建的 GLM-5.4 凭借 Loop Transformer 架构，实现了可与 2T–3T 参数规模模型相媲美的智能水平。

30B 受控等参数消融实验

在与 750B 基座完全同构的 30B 模型上，团队开展了受控等参数对比实验：在参数量完全一致且总训练计算量仅增加约 10% 的条件下，循环版本相比非循环基线在 200K 长上下文 SFT 后（开启思考模式）展现出明确且全面的性能提升（具体对比数据见下图）。

从该组消融实验中得出了两项尤为突出的核心结论：

  1. 更长的推理链条受益更为显著：循环架构带来的最大性能增幅集中在数学、科学推理与长上下文任务领域，而这些正是支撑广义编程（Generalized Coding）的核心推理能力。
  2. 用于思考的输出 Token 显著减少：在 GPQA-Diamond 和 MMLU-Pro 等绝大多数基准测试中，循环模型的平均输出长度缩短了 10%–14%，其主要来源是思维链（chains of thought）长度的精简。从本质上讲，原本需要通过显式输出 Token（explicit output tokens）展开的部分推理计算，被成功转移到了循环架构所提供的隐式计算深度（implicit depth）之中。

稀疏注意力索引复用与推理部署性能

  • 稀疏索引复用精度验证：在第二轮循环中直接复用第一轮生成的稀疏注意力索引时，实验结果表明其精度表现与每一轮重新计算索引几乎完全一致，同时实现了零额外索引计算开销。
  • 线上推理吞吐实测：借助算法级优化（混合 KV Cache、稀疏索引复用）与系统级核心核函数融合，GLM-5.4 在非高峰时段吞吐最高可达 200 tokens/s，在高峰负载下稳定保持 70–80 tokens/s。
  • 超长上下文部署成本：在 1M 上下文长度下，由于额外循环仅增加一个局部滑动窗口的 KV 缓存开销，GLM-5.4 相比 GLM-5.3 的部署成本增幅被有效控制在较低水平。
  • 行为局限性观察：在实际表现中，GLM-5.4 仍倾向于陷入过长的“马拉松式思考”循环，但这种延长的反思与自我修正过程确实持续推动了准确率超越其自身参数量级的上限。

结论与未来展望

GLM-5.4 是研究团队在循环架构（looped architectures）方向迈出的第一步，成功验证了通过循环机制扩展计算深度（computational depth）在超大参数规模下的有效性与工程可行性，并以此拉开了广义编程（Generalized Coding）的序幕。面向未来，团队明确了若干尚未完全解答的开放问题与演进方向：

  • 自适应计算（Adaptive Compute）：探索如何使模型根据输入难度动态分配循环计算量，让难度更高的 Token 自动获得更多次迭代精炼。
  • 双重扩展下的收益规律：系统研究当循环次数（loop count）与模型规模（model size）持续同步增长时，循环机制所带来的边际收益将呈现何种扩展规律。
  • 深度扩展与规模扩展并行推进：团队明确指出并非在“扩展深度（scaling depth）”与“扩展模型规模（scaling model size）”之间做出取舍，而是坚持两条路线同步推进。GLM-5.4 已经验证了计算深度的价值，团队下一代参数规模显著更大的旗舰模型将全面承袭此次探索积累的全部经验，并预计在不久后发布。
