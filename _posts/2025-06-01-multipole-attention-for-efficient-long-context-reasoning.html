Multipole Attention for Efficient Long Context Reasoning

作者/机构: Coleman Hooper, Sebastian Zhao, Luca Manolache, Sehoon Kim, Michael W. Mahoney, Yakun Sophia Shao, Kurt Keutzer, Amir Gholami (University of California, Berkeley; ICSI; LBNL)

A1 主要贡献

大型推理模型（Large Reasoning Models, LRMs）通过在测试时利用额外的计算来解决复杂问题，展现了有前景的准确性提升。这些模型为了在回答前进行“思考”，需要生成数千个词元的长思维链（chain-of-thought）。这种长自回归推理过程带来了巨大的推理效率挑战，特别是导致了庞大的键/值（KV）缓存内存占用。虽然稀疏注意力方法可以通过在每个生成步骤只加载重要的KV缓存词元来减少内存瓶颈，但这些方法可能引入错误，扰乱推理过程，导致不可接受的准确性损失，尤其是在需要复杂推理的问题解决任务上。此外，现有方法通常需要对输入进行预处理以便在生成过程中识别重要的提示词元，而这种预处理很难对新生成的推理词元进行在线操作。

为了解决这些挑战，本文在【索引15，Squeezed attention: Accelerating long context length llm inference，2024a】的基础上提出了多极注意力（MULTIPOLE ATTENTION）。该方法通过稀疏注意力加速自回归推理，仅对最重要的词元计算精确注意力，同时对其余词元保持近似表示以维持高准确率。


图 1: MULTIPOLE ATTENTION 算法的可视化。对于重要的键（与当前查询接近），我们计算精确的注意力。对于距离当前查询较远的键，我们使用与代表性质心的注意力分数来近似对这些键的注意力。随着离查询越来越远，我们使用越来越粗粒度的质心。这使我们能够保留序列中所有词元的重要上下文信息，同时仅需要加载少量键进行精确的注意力计算。

该方法的核心思想如 图 1 所示：首先对键（keys）进行聚类，为每个簇计算一个代表性质心。在计算注意力时，方法将当前查询（query）与质心进行比较，以确定键词元的重要性。对于得分最高的键，计算精确注意力；对于其余的键，则利用簇质心来近似计算该簇中所有键的注意力分数，从而保留来自完整KV缓存的上下文信息。本文还提出了该方法的分层泛化版本，随着与查询的距离增加，使用越来越粗粒度的质心。为了加速对先前生成的推理词元的注意力计算，本文还设计了一种快速的聚类更新策略，允许方法加速对先前输出词元的注意力。

具体贡献如下：

  • 多极近似（Multipole Approximation）：算法基于语义相似性对键进行聚类，并用一个代表性的键质心来表示簇内的所有键。计算注意力时，通过比较当前查询与键质心来识别哪些键是重要的，只对这些重要的键计算精确注意力，而用与簇质心的注意力分数来近似其余键的注意力。这使得算法即使在低KV缓存预算下也能保持上下文相关信息。本文还将此方法扩展为分层多极近似，以提高质心比较的效率。
  • 快速在线聚类（Fast Online Clustering）：为了加速对生成过程中附加的KV缓存条目的注意力计算，本文设计了一种快速的聚类更新算法。该算法首先将新词元分配到簇中，然后对所有键进行少量优化步骤以确保高质量的聚类。为了提高算法的可扩展性，本文利用分块k-means聚类方法（将输入序列分段聚类），并设计了一种移位窗口方法，以确保最后一个块总有足够的词元进行聚类。这些优化共同促进了对生成输出词元的高效聚类。
  • 系统实现（System Implementation）：本文展示了一个原型系统实现，其中包含用于执行多极近似注意力的自定义Triton核。该系统实现由一个多阶段核组成，该核将传入的用户查询与键质心进行比较，然后为重要键计算精确注意力，为次重要键计算近似注意力。该方法在长上下文推理应用中，解码阶段的注意力计算实现了高达4.5倍的加速。

A3 背景知识/关键Observation/设计原则

2.1 推理模型

推理模型已成为解决复杂问题解决任务的新范式【索引13，Deepseek-r1: Incentivizing reasoning capability in llms via reinforcement learning，2025】、【索引26，Qwq-32b: Embracing the power of reinforcement learning，2025】。这些模型被训练来生成思维链推理轨迹，其中包含引导模型得出正确答案的逐步推理【索引30，Chain-of-thought prompting elicits reasoning in large language models，2022】。DeepSeek-R1模型【索引13，Deepseek-r1: Incentivizing reasoning capability in llms via reinforcement learning，2025】开创了一种新的基于强化学习的方法，用于训练解决问题的推理模型。其发布的模型还包括基于Llama3【索引12，The llama 3 herd of models，2024】和Qwen2.5模型系列【索引33，Qwen2.5 technical report，2024】的较小开源模型（从其基础模型蒸馏而来）。此外，还发布了几个具有代理工具调用能力的强大推理模型，如QwQ-32B模型【索引26，Qwq-32b: Embracing the power of reinforcement learning，2025】、Qwen3模型系列【索引33，Qwen2.5 technical report，2024】和Llama-Nemotron模型系列【索引6，Llama-nemotron: Efficient reasoning models，2025】。

2.2 长上下文推理

支持超过10万词元上下文长度的长上下文大语言模型（LLM）已广泛应用于文档问答、摘要、文献综述和处理多轮对话等应用。已有多款闭源模型支持长上下文能力【索引1，Gpt-4 technical report，2023】、【索引3，Claude 2，2023】，包括支持超过100万上下文长度的Gemini【索引11，Gemini 1.5，2023】。新的开源模型家族，如Llama3【索引22，Llama 3.1，2024】和Qwen2.5【索引33，Qwen2.5 technical report，2024】，也支持超过10万的上下文长度。另一条研究路线则专注于通过缩放或调整位置嵌入来将预训练模型的上下文窗口扩展到其原始支持的上下文长度之外【索引7，Extending context window of large language models via positional interpolation，2023】、【索引25，Yarn: Efficient context window extension of large language models，2023】。

2.3 KV缓存压缩

KV缓存压缩已成为实现长上下文长度推理的关键算法工具。对于长上下文推理场景，KV缓存成为主要的内存瓶颈，使得KV缓存压缩对于高效推理至关重要【索引16，Kvquant: Towards 10 million context length llm inference with kv cache quantization，2024b】。压缩KV缓存的常用方法包括量化【索引16，Kvquant: Towards 10 million context length llm inference with kv cache quantization，2024b】、【索引20，Kivi: A tuning-free asymmetric 2bit quantization for kv cache，2024b】（旨在压缩每个词元的表示）和稀疏化【索引28，Quest: Query-aware sparsity for efficient long-context llm inference，2024】、【索引15，Squeezed attention: Accelerating long context length llm inference，2024a】、【索引36，H2o: Heavy-hitter oracle for efficient generative inference of large language models，2024b】（旨在仅加载重要的KV缓存词元）。

一种减少KV缓存大小的先前方法是KV缓存驱逐。在这种方法中，次重要的词元在生成过程中被驱逐以减少内存消耗。先前的工作利用注意力分数贡献等指标【索引36，H2o: Heavy-hitter oracle for efficient generative inference of large language models，2024b】来选择从KV缓存中驱逐的词元。驱逐词元的一个挑战是它会不可逆地丢弃次重要的词元——如果这些词元在后续生成中变得重要，它们将无法恢复。KV缓存合并【索引29，Model tells you where to merge: Adaptive kv cache merging for llms on long-context tasks，2024】、【索引34，Weightedkv: Attention scores weighted key-value cache merging for large language models，2025】被提出作为一种解决方案，以补偿KV缓存剪枝引起的误差。KV缓存合并涉及将被驱逐的KV缓存条目（基于键的相似性【索引29，Model tells you where to merge: Adaptive kv cache merging for llms on long-context tasks，2024】或历史注意力分数【索引34，Weightedkv: Attention scores weighted key-value cache merging for large language models，2025】）合并，而不是完全丢弃它们。与这些工作相比，我们的算法保留了完整的原始KV缓存（从而允许模型在任何先前的KV缓存状态在生成过程中变得重要时准确地引用它们），同时使用键质心来近似对次重要簇的注意力。


图 2: 概述 MULTIPOLE ATTENTION 如何识别和保留重要的键，同时近似对剩余键的注意力的图表。a) 我们首先通过执行 k-means 聚类来构建一个键索引（从而为每个簇获得一个代表性质心）。b) 在计算注意力时，我们将当前查询与质心进行比较，以估计每个簇中键的重要性（“质心查找”）。c) 对于最重要的（“高分”）键质心，我们然后与相应簇中的键计算精确的注意力。对于剩余的键，我们使用对该簇的代表性质心的注意力来近似对每个键簇的注意力。总的来说，MULTIPOLE ATTENTION 在保留来自完整序列的重要上下文信息的同时，实现了稀疏注意力的效率。我们的方法也可以推广到一种分层方法，如第 3.4 节所述。

另一种利用稀疏性处理KV缓存的常用方法是保留完整的KV缓存，但在每个解码步骤仅加载所需的KV缓存条目。之前的一项工作QUEST【索引28，Quest: Query-aware sparsity for efficient long-context llm inference，2024】将连续的KV缓存条目分组，并为每个组内的键导出代表性向量，然后将查询与这些代表性向量进行比较，以决定加载哪些KV缓存条目。然而，QUEST是基于位置邻近性对键进行聚类，Squeezed Attention【索引15，Squeezed attention: Accelerating long context length llm inference，2024a】则基于语义相似性对键进行聚类，从而能够精确识别可能得分高的词元。另一项相关工作Tactic【索引38，Tactic: Adaptive sparse attention with clustering and distribution fitting for long-context llms，2025】基于语义相似性进行聚类，然后使用分布拟合来选择关键的KV缓存条目。其他先前的工作将查询-键比较框架化为检索问题，以便使用向量搜索方法加速注意力【索引35，Pqcache: Product quantization-based kvcache for long context llm inference，2024a】、【索引19，Can llms maintain fundamental abilities under kv cache compression?，2025】、【索引14，A2 ATS: Retrieval-based kv cache reduction via windowed rotary position embedding and query-aware vector quantization，2025】。与现有方法不同，我们的方法旨在识别并仅加载一小部分KV缓存条目进行精确的注意力计算，同时近似计算对其余KV缓存条目的注意力。我们的算法基于语义相似性对键进行聚类，然后执行快速的质心比较来识别重要的键，同时还利用这些代表性质心来近似对那些未被质心查找检索到的键的注意力。附录A提供了对稀疏加载KV缓存条目方法的更详细讨论。

A2 方法细节

3.1 检索重要的KV缓存词元

使用k-means聚类和质心来识别重要KV缓存条目。为了能够识别和检索重要的KV缓存条目，我们首先使用k-means聚类根据语义相似性对键进行聚类。然后，我们通过取每个簇中所有向量的均值来为每个簇导出代表性质心，这些质心可用于快速估计每个键簇的重要性（如【索引15，Squeezed attention: Accelerating long context length llm inference，2024a】中所述）。为了确定簇i中的键对于给定的查询词元q是否重要，我们将查询与该簇的键质心进行比较，以估计相应键的注意力分数：

$$S_{i}=\frac{\exp \left(q K_{c_{i}}^{\top}\right)}{\sum_{j} N_{j} \cdot \exp \left(q K_{c_{j}}^{\top}\right)},$$

其中$K_{c_j}$是簇j的键质心，$N_j$是簇j中的键的数量。然后，我们可以使用质心注意力分数来识别可能得分高的簇，并仅加载这些簇中相应的键进行精确的注意力计算。为了决定保留哪些键，我们根据质心分数对簇进行排序，然后保留簇直到达到目标词元预算。请注意，对于支持分组查询注意力的模型，我们通过对共享键和值的查询头之间的估计注意力进行平均来聚合重要性【索引2，Gqa: Training generalized multi-query transformer models from multi-head checkpoints，2023】。

处理旋转位置编码（RoPE）对聚类的影响。在对键进行聚类时，一个挑战是旋转位置编码（RoPE）的影响，它会根据序列中的位置对键向量进行不同程度的旋转。这意味着在序列中不同位置的语义相似的键可能不会被聚类在一起。为了解决这个问题，我们在计算质心时采用了【索引14，A2 ATS: Retrieval-based kv cache reduction via windowed rotary position embedding and query-aware vector quantization，2025】中的窗口化RoPE策略（该策略假设查询和键向量之间存在固定的相对位置差异），从而提高了键向量的可聚类性。然后，在执行质心查找时，我们使用在固定位置旋转的查询向量（如【索引14，A2 ATS: Retrieval-based kv cache reduction via windowed rotary position embedding and query-aware vector quantization，2025】中所述）。

3.2 重要性感知的多极近似

使用质心近似次重要词元的注意力。在使用质心查找识别出重要词元后，我们的目标是近似对次重要词元的注意力，以保留必要的上下文信息。我们直接使用公式1中与簇质心的注意力分数作为该簇的估计注意力分数。我们还为每个簇缓存一个代表性的值质心$V_c$（即给定键簇对应的值向量的平均值）。簇i的注意力贡献（不包括Softmax分母）可以表示如下：

$$N_i \exp (q K_{c_i}{}^\top) V_{c_i}$$

其中$N_i$, $K_{c_i}$ 和 $V_{c_i}$ 分别是簇i的键数量、键质心和值质心。对于次重要的键簇，我们使用公式2计算每个簇的注意力贡献。然后，我们将精确注意力的输出（针对重要词元）和来自质心的输出（针对次重要词元）合并，以获得最终的注意力输出。我们的算法在图2中进行了可视化，该图展示了我们如何利用键质心来识别当前查询的重要键，以及近似对次重要键的注意力。

3.3 高效在线聚类

在线聚类的挑战与方法。在长文本生成应用中使用我们的方法时，一个关键挑战是需要对生成的词元进行注意力近似。这要求在新的词元附加到KV缓存时更新簇和相应的质心；然而，如果需要对整个序列重新运行聚类，这将是计算密集型的。为了在附加新生成的词元时快速更新簇和相应的质心，我们采用了两种方法：一种是分块聚类方法（带有滑动窗口来管理附加新词元时块之间的转换），另一种是为新附加的词元进行快速初始簇分配，然后进行少量的簇优化步骤。

分块聚类与滑动窗口机制。图3概述了我们的分块聚类方法，以确保在向质心追加数据时，我们不需要对整个序列进行重新聚类。我们在大小为W个词元的块中执行聚类，这意味着当我们附加新词元时，我们只需要对最后一个块进行重新聚类。此外，如果最后一个块被限制为W个词元，在超过此限制后，直到有足够数量的新词元被附加之前，对后续词元进行聚类将很困难。因此，我们允许最后一个块扩展到 $\alpha + W$ 个词元，然后才将该块的前W个词元移除并单独聚类。这确保了最后一个块的词元数不少于$\alpha$个，意味着最后一个块始终包含足够数量的键用于聚类。请注意，分块聚类方法还改善了预填充（prefill）期间的聚类运行时间，提高了我们算法的可扩展性。

快速聚类更新过程。此外，为了加速更新过程，我们从附加的词元中随机采样额外的初始质心，然后利用快速的初始分配将附加的词元分配给最近的质心，并相应地更新这些词元映射到的质心（这类似于序列k-means算法的批处理版本【索引21，Some methods for classification and analysis of multivariate observations，1967】）。这个过程只需要对新附加的词元运行，因此其运行时开销极小。在运行这个单次更新后，为了确保高聚类精度，我们在最后一个块上运行少量迭代的完整k-means来优化质心和质心分配。


图 3: 我们的分块聚类方法和在生成过程中更新簇的滑动窗口方法的可视化。我们将键聚类成 W 个词元的块，除了最后一个块，它包含最后的 α 到 W + α 个词元。当我们更新簇时，我们只需要更新最后一个窗口。一旦最后一个窗口达到 W + α 个词元，我们将其分成前 W 个词元（成为一个独立的块）和最后的 α 个词元（成为我们附加新键的新最终块）。

3.4 分层多极注意力

分层方法的动机。尽管我们的方法允许在保持准确性的同时剪枝大部分KV缓存条目，但聚类的粒度需要足够精细以实现准确的检索和近似。然而，如果我们需要比较的质心数量随着上下文长度的增加而增长，这可能导致质心查找成为瓶颈。特别是在我们推向更激进的稀疏性方案时，质心查找的开销变得更加突出。

分层多极近似的实现。为了减轻质心查找的开销，同时仍然为整个KV缓存提供准确的近似，我们将【索引15，Squeezed attention: Accelerating long context length llm inference，2024a】中的分层质心查找方法扩展为注意操作的分层多极近似。我们执行分层k-means聚类，以导出逐渐粗粒度的簇质心。这种分层聚类与第3.3节中描述的快速在线聚类更新兼容，因为分块聚类方法可以应用于层次结构的每个级别。在质心查找的每个级别，我们识别少量有希望的键质心（对于这些质心，我们需要与下一级的精细质心进行比较），然后使用与键质心的注意力来近似次重要的键。

两级分层近似的例子。在有两级层次结构的情况下，我们首先将查询与粗粒度（第一级）质心进行比较，以确定键的哪些区域可能重要。这个初始查找使我们能够仅对可能得分高的质心执行细粒度（第二级）质心比较。此外，对于低重要性的第一级质心，我们可以使用与第一级质心的注意力来近似相应簇中所有词元的注意力。然后，我们仅对有希望的细粒度质心执行第二级质心查找。在这里，我们识别最重要的词元（需要加载以进行精确的注意力计算），并近似其余仅重要到足以达到第二级质心查找的词元的注意力。这个渐进式优化过程使我们能够根据键的重要性采用更准确的近似。总的来说，我们的分层多极算法减少了质心比较的开销，同时在查找的每一步仍然为次重要的键提供准确的近似。

4 系统实现

自定义Triton核。我们为计算质心查找、稀疏Flash解码和质心替换操作实现了自定义的Triton核。这些核遵循了FlashAttention-2【索引9，Flashattention-2: Faster attention with better parallelism and work partitioning，2023】的并行化策略，包括跨注意力头和沿查询序列长度维度拆分计算，以及FlashDecoding【索引10，Flash-decoding for long-context inference，2023】的策略，其中计算跨KV维度拆分，并对中间结果进行归约。我们还建立在现有稀疏FlashAttention核的工作基础上【索引24，Fast attention over long sequences with dynamic sparse flash attention，2023】、【索引15，Squeezed attention: Accelerating long context length llm inference，2024a】。

第一阶段：质心查找。我们核实现的第一阶段（质心查找）旨在将查询与键质心进行比较，以识别重要的词元（如【索引15，Squeezed attention: Accelerating long context length llm inference，2024a】中所述）。在获得与质心的注意力分数后，我们收集每个词元的质心分数，并应用top-K来识别在固定词元预算下可以保留哪些得分最高的键簇。

第二、三阶段：稀疏FlashDecoding与质心替换。在识别出重要和次重要簇后，我们核实现的下一阶段（稀疏FlashDecoding）计算来自选定（重要）簇的键的注意力输出。该核接受一个包含键索引的张量作为输入，并仅加载与这些索引相对应的键以进行精确的注意力计算。最后，在我们核实现的第三阶段（质心替换），我们使用与相应质心的注意力来近似对次重要键的注意力。根据公式2，我们需要$exp(qK_{c_i}^\top)$，即查询与键质心比较的结果。鉴于这些值在质心查找期间已计算，我们修改了质心查找核以保存这些值，然后在替换核中加载它们（以避免在替换阶段重新加载键质心）。我们还从质心查找中返回一个布尔掩码，该掩码识别哪些质心是次重要的，以便仅对这些质心执行替换。质心替换核加载来自质心查找的查询-键质心点积结果，然后计算与值质心的注意力。注意力输出随后与稀疏FlashDecoding核的输出合并。

快速聚类更新的实现。对于我们的快速聚类更新，我们使用PyTorch级别的原语（包装在torch.compile中以减少核启动开销）来实现。我们使用一个大小为L到2L的固定本地词元缓冲区，这些词元未被聚类，并在每个解码步骤中被精确加载。我们每L个解码步骤将缓冲区中最老的L个词元附加到簇中。执行聚类后，我们缓存键和值质心，以避免在每个生成步骤中重新计算这些值。

A5 结论

推理能力已成为LLM解决复杂问题的关键推动力。虽然通过长思维链解码进行推理对于在复杂任务上实现高准确性至关重要，但由于在给出答案前需要生成数千个词元，这带来了巨大的效率成本。稀疏注意力方法可以通过减少加载KV缓存的内存带宽需求来加速解码，但这些方法在激进的稀疏度设置下会导致显著的准确性损失。

本文通过引入MULTIPOLE ATTENTION来解决这些挑战。该方法通过仅加载少量条目进行精确注意力计算，同时为其余词元保留近似表示，从而减少了KV缓存的内存需求。我们的算法首先根据语义相似性对键进行聚类，然后使用相应的簇质心来选择重要的键向量并近似对次重要键的注意力，从而保留了来自完整序列的重要上下文信息。我们还设计了一种快速的聚类更新策略，以便快速地重新聚类输入以包含新生成的词元，这使我们能够加速对先前输出词元的注意力计算。我们在新兴的推理模型和困难的长上下文推理任务上评估了我们的方法，表明我们的方法可以在激进的KV缓存稀疏设置下保持复杂推理任务的准确性。我们还展示了高效的核实现，证明我们的算法可以在长上下文推理应用中将注意力加速高达4.5倍。

A7 补充细节

7 局限性

本方法的局限性。我们方法的一个局限性是它专注于加速生成过程，而没有加速预填充（prefill）阶段的注意力计算。未来工作的一个可能方向是扩展我们的方法以支持加速预填充。另一个局限性是，在现有的LLM服务框架中支持我们的方法需要额外的实现工作。第三个局限性是，我们的方法需要额外的内存来存储质心（尽管这个开销相对于整个KV缓存的大小来说很小）。

A6 附录

A 扩展相关工作：仅加载重要的KV缓存条目

一种稀疏注意力方法是保留完整的KV缓存，但只在每个解码步骤加载所需的条目。这些方法常用的一种识别重要KV缓存条目的技术是聚类。QUEST【索引28，Quest: Query-aware sparsity for efficient long-context llm inference，2024】将连续的KV缓存条目分组，并为每个组内的键派生代表向量。其方法通过将当前查询与代表向量进行比较来执行检索，以确定该组是否重要并需要加载以进行精确的注意力计算。虽然这种方法对连续的键进行分组，但序列中的位置邻近性不一定表明相应键向量的相似性。Squeezed Attention【索引15，Squeezed attention: Accelerating long context length llm inference，2024a】则基于语义相似性对键进行聚类，从而能够精确识别可能得分高的词元。Tactic【索引38，Tactic: Adaptive sparse attention with clustering and distribution fitting for long-context llms，2025】也基于语义相似性对键进行聚类，然后进行分布拟合以帮助预测重要的KV缓存条目。

多项先前的工作将查询-键比较框架化为检索问题，以利用向量搜索方法加速注意力。其中一种方法，PQCache【索引35，Pqcache: Product quantization-based kvcache for long context llm inference，2024a】，执行乘积量化以进行向量搜索来选择重要的键，然后仅使用选定的键计算精确的注意力。A2ATS【索引14，A2 ATS: Retrieval-based kv cache reduction via windowed rotary position embedding and query-aware vector quantization，2025】执行查询感知的向量量化，以实现对重要KV缓存条目的准确检索。RetrievalAttention【索引18，Retrievalattention: Accelerating long-context llm inference via vector retrieval，2024a】在键上构建一个向量索引，以促进重要键的检索，并将完整的KV缓存和向量索引卸载到CPU以执行查找。

与先前工作相比，我们的方法旨在选择并加载一小部分重要词元进行精确的注意力计算，同时为其余的KV缓存条目保持一个近似表示。我们的方法使用聚类来分组语义相似的键，然后通过快速的质心查找来识别重要的键。值得注意的是，我们的键质心也作为每个簇中键的代表向量，因此可以用来近似对那些未被质心查找检索到的键的注意力。这使得我们的方法即使在激进的稀疏设置下（以及对于对KV缓存剪枝敏感的任务），也能保持高准确性。

另一项相关的先前工作是【索引17，Fast multipole attention: A divide-and-conquer attention mechanism for long sequences，2023】，它利用一种受快速多极方法（FMM）启发的方法来加速Transformer中的注意力计算。FMM【索引8，The fast multipole method for the wave equation: A pedestrian prescription，1993】是一种相关的技术，用于加速N体问题的模拟，它将一组点质量近似为单个点质量，并对距离当前关注点更远的质量进行更粗粒度的近似。这种方法类似于我们的算法，我们的算法使用逐渐粗粒度的键质心来近似距离当前查询词元更远的键。然而，与【索引17，Fast multipole attention: A divide-and-conquer attention mechanism for long sequences，2023】根据序列中的位置邻近性对KV缓存条目进行分组不同，我们的方法基于语义相似性对键进行聚类，因此根据KV缓存条目对当前查询的重要性来确定近似的粒度。
