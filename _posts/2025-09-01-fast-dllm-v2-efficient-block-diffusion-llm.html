FAST-DLLM V2: Efficient Block-Diffusion LLM

发表时间: 2025-09 · arXiv:2509.26328

原文: https://arxiv.org/abs/2509.26328

  • 作者/机构: Chengyue Wu (香港大学, NVIDIA), Hao Zhang (NVIDIA), Shuchen Xue (NVIDIA), Shizhe Diao (NVIDIA), Yonggan Fu (NVIDIA), Zhijian Liu (NVIDIA), Pavlo Molchanov (NVIDIA), Ping Luo (香港大学), Song Han (NVIDIA, MIT), Enze Xie (NVIDIA)
速读

一句话结论 本文提出 Fast-dLLM v2，通过仅 1B tokens 的微调将预训练自回归模型高效适配为块扩散语言模型，在保持生成质量的同时实现了比标准自回归解码高达 2.5 倍的推理加速。

要解决什么问题 传统自回归大语言模型采用严格的从左到右逐个 token 生成的方式，这种顺序解码机制严重限制了推理过程中的并行性，导致生成长文本时延迟极高。为了打破这种串行瓶颈，研究者们提出了基于扩散的语言模型，允许多个 token 联合预测以提升并行度。然而，现有的扩散语言模型在实际落地时面临多重卡点：首先是无法有效利用键值缓存（KV 缓存），导致计算冗余、推理延迟依然居高不下；其次是序列长度往往固定，缺乏生成灵活性；最后是训练成本极其高昂，例如现有的 Dream 模型需要消耗约 500B tokens 的数据才能完成从自回归到扩散机制的适配，极大地限制了其普及与扩展。

怎么做的 Fast-dLLM v2 的核心思路是结合自回归和扩散模型的优势，实现“块间自回归生成，块内扩散并行优化”。为了绕开高昂的训练成本，作者设计了一种对自回归极其友好的后训练适配策略。首先将长序列切分为固定大小的块，在每个块内引入部分 token 掩码。为了确保所有 token 都能得到充分训练，模型采用互补掩码策略：将每个样本复制为两个视图，一个使用随机掩码，另一个使用其补集，让模型同时观察跨视图的掩码和未掩码上下文。同时，为了维持预训练模型的时序表示质量，采用移位标签策略，即预测位置 $i$ 的 token 时使用位置 $i-1$ 的隐藏状态。其训练目标是最小化仅针对被掩码 token 的交叉熵损失：$$\mathcal{L}_{\text{block}}(\theta) = -\mathbb{E}_{x,m} \left[ \sum_{i=1}^{L} \mathbf{1}[x_t^i = [\text{MASK}]] \log p_\theta(x_0^i \mid x_{<i}, x_{\text{block}(i)}) \right]$$ 配合精心设计的混合注意力掩码，模型允许块内双向关注和跨块因果关注，仅需约 1B tokens 即可完成无损适配。在推理阶段，模型按块逐个解码并引入分层缓存机制。第一层是块级缓存，将已解码块的未掩码 token 缓存为只读上下文供后续块重用，恢复了跨块的键值缓存能力。在当前块内，模型采用基于置信度的并行解码，迭代优化掩码 token，置信度超过阈值的位置被并行揭开。为了加速这一过程，引入了第二层子块缓存（DualCache），为部分解码的块维护前缀和后缀缓存，在揭示更多 token 时直接复用，彻底排除了昂贵的重新计算。

效果如何 实验基于 Qwen2.5-Instruct 的 1.5B 和 7B 模型，在 64 块 A100 GPU 上使用约 1B 到 3B tokens 的指令微调数据进行训练。对比基线包括代表标准自回归路线的 Qwen2.5-Instruct 和 Qwen2.5-7B-Nemo-FT，以及代表扩散路线的 Dream 和 Fast-dLLM-LLaDA。在 7B 规模上，Fast-dLLM v2 的综合平均分达到 60.3，超过了 Qwen2.5-7B-Nemo-FT（59.6）和 Dream（57.6）。在 GSM8K 数学推理任务中，当并行解码的置信度阈值设为 0.9 时，准确率仅有极小下降，但吞吐量从 39.1 tokens/s 飙升至 101.7 tokens/s，实现 2.6 倍加速。在 A100 和 H100 硬件上，批量大小为 64 时吞吐量分别最高提升 1.5 倍和 1.8 倍。该方法也有其局限性：推理时如果使用的块大小与训练时不匹配，会导致显著的性能下降；此外，子块缓存在极小批量（如批量大小为 1）时带来的吞吐量增益可忽略不计，其效率优势主要在计算密集型的大批量场景下才能充分释放。

A1 主要贡献

本文针对自回归（AR）大语言模型（LLM）固有的顺序解码导致推理效率低下的问题，提出了 Fast-dLLM v2，一个精心设计的块扩散语言模型（dLLM）。该模型旨在将预训练的 AR 模型高效地适配为 dLLM，以实现并行文本生成。

核心问题与研究目标
- 问题: 传统的 AR LLM 采用逐个 token 生成的方式，这种严格的从左到右的顺序限制了其在解码过程中的并行性，导致推理效率不高。
- 替代方案: 基于扩散的语言模型（dLLM）允许多个 tokens 联合预测或优化，理论上具有更高的解码并行度。然而，现有的 dLLM 存在无法有效使用 KV 缓存、推理延迟高、序列长度固定或灵活性受限等缺点。
- 研究目标: 提出一种块扩散语言模型（BD-LM），它结合了 AR 和扩散模型的优点，在块间自回归生成，在块内进行扩散。目标是设计一个能够扩展到大型 LLM 并在真实世界任务中保持高质量文本生成和强大扩展性的模型，同时实现比 AR 模型更快的推理速度。

创新点与主要贡献
1. 数据高效的后训练适配策略: 识别出本文块状注意力设计的 AR 友好特性，并利用此特性提出了一种后训练策略，仅需约 1B tokens 的微调数据即可将预训练 AR 模型适配为块扩散框架，而无需从头开始训练。相比于 Dream (Ye et al., 2025a) 需要约 500B tokens，数据效率提升了 500 倍，实现了无损适配。
2. 分层缓存与并行解码推理策略: 引入了一种结合了分层缓存机制和块状并行解码的推理策略。该设计包括一个用于跨块存储历史上下文表示的块级缓存，以及一个支持在部分解码的块内进行高效并行生成的子块缓存。这有效地重用了上下文信息并加速了块内 token 的生成。
3. 全面的大规模实验验证: 在高达 7B 参数的模型和多样化的任务上进行了广泛实验。结果表明，Fast-dLLM v2 在保持与 AR 基线相当的生成质量的同时，实现了比标准 AR 解码高达 2.5 倍的速度提升，并在 dLLM 中达到了最先进的效率。

A2 方法细节

3.1. 预备知识

基础定义。一个长度为 $L$ 的 token 序列表示为 $x = \{x_1, x_2, . . . , x_L\}$。传统的自回归模型通过建模条件分布 $p_\theta(x_i|x_{<i})$ 来顺序生成 $x$，并通过最小化交叉熵损失进行训练。</p>

扩散语言模型。扩散语言模型通过一个前向加噪过程和一个学习的反向去噪模型来定义生成分布。在时间 $t \in (0, 1)$，原始序列 $x_0$ 中的每个 token 以概率 $t$ 被独立地掩码（masked），产生一个损坏的序列 $x_t$。反向模型 $p_\theta(x_0|x_t)$ 则根据加噪后的输入预测原始的 tokens。


图2 | Fast-dLLM-v2 的训练过程。输入序列逐块解码。在每个块内，模型执行带有部分掩码的下一词元预测。为确保每个词元都得到训练，引入了互补掩码，使得一个视图中被掩码的词元可以从另一个视图中预测。我们只对以绿色高亮显示的预测词元应用损失，虚线连接了掩码词元及其对应的预测。

模型的训练目标是最小化期望的掩码 token 预测损失：

$$\mathcal{L}(\theta)=-\mathbb{E}_{t, x_{0}, x_{t}}\left[\frac{1}{t} \sum_{i=1}^{L} \mathbf{1}\left[x_{t}^{i}=[\mathrm{MASK}]\right] \log p_{\theta}\left(x_{0}^{i} \mid x_{t}\right)\right],$$

其中 $t \sim \text{Uniform}(0, 1)$，$x_t$ 从前向过程中采样。损失仅在被掩码的 tokens 上计算。

3.2. 适配为块扩散 LLM

基于预训练模型的微调框架。我们的块状扩散训练流程建立在预训练的 Qwen2.5-Instruct 模型（包括 1.5B 和 7B 版本）之上，具体实现为在指令调优数据上进行监督式微调（SFT）。每个训练批次都使用我们的块状扩散设置构建。具体而言，我们在每个块内引入部分 token 掩码，并结合互补掩码策略 (Li et al., 2025b)，以确保每个 token 都能在可见和被掩码的上下文中得到训练。整体架构和训练工作流程如图 2 所示。

块状组织。给定一组 tokenized 样本，我们首先通过附加必要的 [MASK] token，将每个序列填充到其长度是块大小 $B$ 的整数倍。这些填充的 tokens 在损失计算中被忽略，且不参与梯度更新。完成对齐后，我们将填充后的序列拼接成一个长的 token 流，并将其分割成固定上下文长度 $C$ 的训练序列。因此，每个打包的序列被自然地划分为 $K = C/B$ 个大小为 $B$ 的不重叠块。这种块对齐的打包方式确保了高效的批处理，同时避免了块边界跨越样本边界。

带有互补视图的掩码令牌预测。对于每个块，我们随机采样一个二元掩码 $m \in {0, 1}^B$，其中 $m_i = 1$ 表示位置 $i$ 被一个学习到的 [MASK] 嵌入所替代。为了确保所有 tokens 在训练过程中都能同时接受到被掩码和未被掩码的监督，我们采用了互补掩码策略：每个训练样本被复制成两个视图，分别使用掩码 $m$ 和其补集 $\bar{m} = 1 - m$。这两个视图被放置在同一个批次中，这样模型可以同时观察到跨视图的掩码和未掩码上下文。

用于预测的令牌移位。为了保持预训练 AR 模型的表示质量 (Ye et al., 2025b,a)，我们采用了一种移位标签（shifted-label）策略：在被掩码的位置 $i$ 预测 token 时，使用其前一个位置 $(i - 1)$ 的 logit。具体来说，如果 $x_t^i$ 被掩码，模型使用位置 $i - 1$ 的隐藏状态来预测 $x_0^i$，这与因果语言模型中的下一 token 预测机制保持一致。这使得 dLLM 在支持块内扩散的同时，能够维持类似 AR 的时序表示。

训练目标。我们最小化仅针对被掩码 token 的交叉熵损失：

$$\mathcal{L}_{\text{block}}(\theta) = -\mathbb{E}_{x,m} \left[ \sum_{i=1}^{L} \mathbf{1}[x_t^i = [\text{MASK}]] \log p_\theta(x_0^i \mid x_{<i}, x_{\text{block}(i)}) \right],$$ <p>其中，$x_{\text{block}(i)}$ 表示包含位置 $i$ 的块中的所有 tokens（包括掩码和未掩码的），$x_{<i}$ 是来自前面块的干净 tokens。

块状注意力掩码。我们使用一种类似于 (Arriola et al., 2025) 中的混合注意力方案。对于每个训练样本，我们将加噪序列 $x_t$ 和其对应的干净序列 $x_0$ 沿序列维度拼接，总长度为 $2C$。然后应用注意力掩码 $M \in {0, 1}^{2C \times 2C}$ 来控制因果连接和双向连接。这种设计允许同时处理损坏和干净的上下文，从而促进互补掩码的监督。该注意力掩码自然地支持块并行性和块间的因果自回归依赖。我们进一步采用 flex-attention 实现来高效地实现这种结构化掩码并加速训练。

3.3. 推理流程

推理策略概述。在推理时，Fast-dLLM v2 采用一种块状解码策略，该策略平衡了 LLM 的自回归特性和扩散解码所提供的并行性。如图 3 所示，生成过程一次一个块地进行：先前解码的块被缓存并作为干净的前缀上下文重用，而当前块则进行并行的掩码 token 优化。

性能优势。通过结合块级缓存、块内并行解码和 DualCache 重用，Fast-dLLM v2 最大化了解码效率，而无需辅助模型或额外的推理开销。根据经验，我们观察到与标准 AR 解码相比，速度提升高达 2.5 倍，同时生成质量与强大的自回归基线相当。这使得 Fast-dLLM v2 成为在延迟敏感应用中实际部署 LLM 的一个有吸引力的选择。

带有缓存的块状自回归解码。由于 Fast-dLLM v2 中的每个块都按因果顺序解码，我们自然地保留了跨块的从左到右的语义。每个块解码后，其未掩码的 tokens 被缓存为只读上下文，供后续块使用。这种设计实现了块级的键值（KV）缓存重用，并显著减少了冗余计算。推理时的注意力掩码允许每个块在内部进行双向关注，同时对前面的块进行因果关注，这与训练期间的配置相呼应。

块内并行优化。为了加速块内的生成，我们采用了 Fast-dLLM (Wu et al., 2025) 中提出的基于置信度的并行解码策略。具体来说，我们根据模型对预测 tokens 的置信度，迭代地优化当前块中被掩码的 tokens。超过置信度阈值的 tokens 将被并行地解码和揭开，而不确定的位置则保持掩码状态以待后续优化。这避免了模糊的预测，并减少了生成延迟。

用于子块重用的 DualCache。为了在块内解码期间进一步减少冗余计算，我们集成了来自 Fast-dLLM 的 DualCache 机制。DualCache 为部分解码的块维护前缀和后缀的 KV 缓存，从而在揭示更多 tokens 时实现高效的重新计算。这种分层缓存不仅排除了昂贵的重新计算，还支持了基于置信度的优化中所使用的迭代式、选择性解码模式。

带填充的批量解码。为了支持对不同目标长度序列的批量生成，我们用 [MASK] tokens 对每个序列进行右填充，使其总长度能被块大小 $B$ 整除。然后将这些序列分组并逐块解码。在每一步中，批次中的所有序列都并行解码下一个块，无论还剩下多少真实的 tokens，从而确保在现代硬件上实现一致且高效的调度。

A4 实验环境

  • 模型架构: 在 Qwen-2.5 1.5B 和 7B Instruct 模型上进行适配实验。
  • 数据集: 使用 LLaMA-Nemotron 后训练数据集 (Bercovich et al., 2025) 的一个子集进行监督式微调。

  • 硬件配置:

    • GPU: 64 块 NVIDIA A100 GPUs。
    • 吞吐量测试还包括了 NVIDIA H100 GPUs。

  • 软件配置:

    • 训练框架: 使用 DeepSpeed Zero-3 进行训练。
    • 评估框架: 代码相关基准（HumanEval, MBPP）使用 EvalPlus 框架评估；其他所有基准使用 LM-Eval 框架评估。

  • 训练超参数:

    • 上下文长度: 2048。
    • 批量大小: 256。
    • 1.5B 模型: 学习率 $2 \times 10^{-5}$，训练 6,000 步 (约 31.5 亿 tokens)，训练时长约 8 小时。
    • 7B 模型: 学习率 $1 \times 10^{-5}$，训练 2,500 步 (约 13.1 亿 tokens)，训练时长约 12 小时。

  • 默认推理配置 (除非另有说明):

    • 子块大小: 8。
    • 块大小: 32。
    • 并行解码: 禁用（阈值为 1）。

A4 实验结果

主要性能与速度结果

  • 模型性能:

    • 在 1.5B 规模上，Fast-dLLM v2 平均分达到 45.0，优于 Qwen2.5-1.5B 基线，并成为 1B 规模扩散模型和 NTP 训练的自回归模型中的新 SOTA。
    • 在 7B 规模上，Fast-dLLM v2 平均分达到 60.3，超过了包括 Qwen2.5-7B-Nemo-FT (59.6) 和 Dream (57.6) 在内的所有基线。

    • 在计算受限的场景（如 batch size=32）下，子块缓存能提供显著的加速。
    • 结论是在实际的批量大小下，结合较大的子块和缓存能带来强大的性能与效率优势。

A5 结论

本文提出了 Fast-dLLM v2，一个可扩展的块扩散语言模型框架，它能够将预训练的自回归 LLM 高效地适配为用于并行文本生成的扩散式解码器。通过将块状扩散机制与互补掩码相结合，Fast-dLLM v2 在保留原始 AR 模型预测能力的同时，实现了块内的双向上下文建模。为了解决现有扩散模型的延迟问题，我们进一步提出了一种分层缓存策略，包括用于块间上下文重用的块级缓存和基于 DualCache 的用于块内高效优化的子块缓存，并结合了并行解码流程。在大型 Qwen2.5-Instruct 模型（1.5B 和 7B）上的广泛实验表明，Fast-dLLM v2 在不损失生成质量的情况下，实现了比标准 AR 解码高达 2.5 倍的速度提升，持续匹敌强大的 AR 基线，并在效率上超越了先前的扩散模型。这些结果凸显了块扩散框架作为在现实世界应用中部署高质量、低延迟 LLM 的一条可行路径的潜力。

A.2. 注意力掩码设计

混合注意力掩码。为了在输入的损坏视图和干净视图之间实现高效和结构化的学习，我们使用了一种自定义的块感知注意力方案 (Arriola et al., 2025)。在每个训练步骤中，我们将加噪序列 $x_t$ 和干净序列 $x_0$ 拼接成一个总长度为 $2C$ 的单一输入，然后通过一个注意力掩码 $\mathcal{M}_{\text{full}} \in \{0, 1\}^{2C \times 2C}$ 应用混合注意力模式。

条件概率建模。为了简化表示，我们沿用先前工作的做法，略微滥用符号 $x_k$，在此上下文中它表示第 $k$ 个块中的 tokens 集合（而非早期章节中的第 $k$ 个 token）。具体来说，我们的目标是为所有块 $k \in [1, K]$ 建模条件概率 $p(x_k | x_t^k, x_{<k})$，其中 $x_t^k$ 是块 $k$ 的加噪版本，$x_{<k}$ 包含先前块中的所有干净 tokens。这种表述使我们能够通过将它们的拼接序列送入 transformer 并应用如图 7(a) 所示的精心构建的注意力掩码 $\mathcal{M}_{\text{full}}$，来同时处理加噪和干净的表示。</p>

掩码分解。整体注意力掩码可以分解为四个子掩码：

$$\begin{aligned} \mathcal{M}_{\text{full}} = \begin{bmatrix} \mathcal{M}_{BD} & \mathcal{M}_{OBC} \\ 0 & \mathcal{M}_{BC} \end{bmatrix}, \end{aligned}$$

其中：
- $\mathcal{M}_{BD}$ (块对角掩码): 在加噪序列 $x_t$ 中，为同一块内的 tokens 提供双向自注意力，以实现块内优化：

$$\begin{aligned} [M_{BD}]_{ij} = \begin{cases} 1 & \text{if } i,j \text{ belong to the same block} \\ 0 & \text{otherwise} \end{cases} \end{aligned}$$


- $\mathcal{M}_{OBC}$ (偏移块因果掩码): 允许 $x_t$ 中的每个加噪 token 关注干净序列 $x_0$ 中先前块的 tokens，从而保持块间的因果条件：

$$\begin{aligned} [M_{OBC}]_{ij} = \begin{cases} 1 & \text{if } j \text{ is in a block before } i \\ 0 & \text{otherwise} \end{cases} \end{aligned}$$
- $\mathcal{M}_{BC}$ (块因果掩码): 允许干净序列 $x_0$ 中的每个 token 关注所有先前和当前块的位置，以促进类似自回归的进程：
$$\begin{aligned} [M_{BC}]_{ij} = \begin{cases} 1 & \text{if } j \text{ is in the same or an earlier block as } i \\ 0 & \text{otherwise} \end{cases} \end{aligned}$$
这个组合掩码允许统一处理掩码 token 预测、同时以先前的已知上下文为条件，并通过块并行性实现结构化的训练效率。

推理时的注意力机制。在推理时，我们采用一种简化的因果注意力机制，将已解码的块作为固定的前缀上下文重用。如图 7(b) 所示，先前生成的块 $x_{<k}^0$ 被缓存以避免冗余计算，只有当前的加噪块 $x_t^k$ 被主动优化。该块在内部进行双向关注，类似于训练时的 $\mathcal{M}_{BD}$，同时对先前块中的未掩码 tokens 进行因果关注。因此，注意力计算被限制在当前块及其因果前缀上，通过键值缓存重用和减少内存占用实现了高效解码。这种结构在保持跨块从左到右语义的同时，允许块内去噪并行进行。</p>

A.3. 训练目标细节

损失函数。我们最小化仅针对掩码 token 的交叉熵损失：

$$\mathcal{L}_{\text{block}}(\theta) = -\mathbb{E}_{x,m} \left[ \sum_{i=1}^{L} \mathbf{1}[x_t^i = [\text{MASK}]] \log p_\theta(x_0^i \mid x_{<i}, x_{\text{block}(i)}) \right].$$ <p>归一化系数的省略。值得注意的是，该目标函数似乎省略了标准掩码建模损失中常见的归一化系数 $1/L$（例如，除以掩码 token 的数量）。这是有意为之的，并由我们的互补掩码策略来证明其合理性。因为我们为每个训练样本 $x_0$ 使用一个互补掩码：我们总是采样两个互补的时间 $t$ 和 $1-t$，对应掩码 $m$ 和 $\bar{m} = 1 - m$。

$$-\left[\sum_{i=1}^{L} \mathbf{1}\left[x_{t}^{i}=[\mathrm{MASK}]\right] \log p_{\theta}\left(x_{0}^{i} \mid x_{<i}, x_{\mathrm{block}(i)}\right)\right]+\left[\sum_{i=1}^{L} \mathbf{1}\left[x_{1-t}^{i}=[\mathrm{MASK}]\right] \log p_{\theta}\left(x_{0}^{i} \mid x_{<i}, x_{\mathrm{block}(i)}\right)\right].$$ <p>由于互补掩码的存在，对于任何给定的样本 $x_0$，对损失有贡献的 token 总数始终是完整的序列长度 $L$。

$x=-3 \text{ and } x=2$

由于函数在 $x = -3$ 和 $x = 2$ 处无定义，所以在这些点存在垂直渐近线。

助手

要确定送货卡车需要多少趟才能送出 960 个箱子，我们首先注意到卡车一次的运载能力。卡车一次可以运送 120 个箱子。我们需要计算运输 960 个箱子需要多少趟。

我们可以将这个问题设为一个除法问题：

$$\text{Number of trips} = \frac{\text{Total number of boxes}}{\text{Capacity of the truck per trip}}$$

将给定值代入方程，我们得到：

$$\text{Number of trips} = \frac{960}{120}$$

接下来，我们进行除法运算：

$$\frac{960}{120}=8$$

因此，卡车需要 8 趟才能送出 960 个箱子。
